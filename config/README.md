# 設定管理

シナリオ、環境、秘密情報、配備結果を分けます。Fabric データ基盤用の [fabric.example.json](fabric.example.json) と設定読込みを実装しました。現在の入力は `environment`、`tenantId`、`workspaceId`、`includeOntology` の 4 項目です。アプリ・同期・Foundry の設定は未移植です。

| 区分 | 想定する内容 | Git への扱い |
| --- | --- | --- |
| シナリオ宣言 | ID、版、言語、通貨、タイムゾーン、原本、利用機能 | 公開可能。シナリオ側で管理 |
| 環境ひな形 | 接続先や資源 ID の項目、必要なスコープ、入力の説明 | 実環境値なしで公開 |
| 環境別入力 | テナント、ワークスペース、資源、モデルデプロイ、リダイレクト URI | 原則として Git 管理外 |
| 秘密情報 | API キー、接続文字列、アクセストークン | 環境変数や秘密情報ストア。生成物・ログにも出さない |
| 配備結果 | 作成した資源 ID、操作 ID、実行状態、出力先 URL | 環境別の非公開出力領域 |
| ブラウザー設定 | 必要な公開エンドポイント、クライアント ID、利用可能な機能 | 許可リストで抽出して生成 |

ID や公開エンドポイントは、それ自体がパスワードとは限りません。それでも既存デモの環境を誤操作しないよう、初期値として埋め込みません。ブラウザー向けの `VITE_*` 設定に秘密情報を入れません。

現行の `plan` は `--config` または明示的な環境引数のどちらか一方を使用し、併用を拒否します。暗黙の環境ファイル探索や既存デモへの接続はしません。認証は Azure CLI が管理し、設定ファイルには資格情報を含めません。詳細は [構築手順](../docs/data-foundation.md) を参照してください。

ファイル名だけに頼った一括除外は行いません。環境別生成物は非公開の出力領域、再配布可能な生成済み合成データはシナリオ、API クライアントなどの生成コードは各アプリに区別して配置します。生成コードを Git に含めるかは、移植時にビルド再現性を確認して決めます。
