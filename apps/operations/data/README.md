# データ仕様

## サマリー

[seed.json](seed.json)、[blend-seed.json](blend-seed.json)と[生成処理](../scripts/export-data.mjs)から、画面用 [dataset.json](dataset.json)・[blend-dataset.json](blend-dataset.json)、40 種の分析用 CSV、40 種の Ontology 用 CSV、TTL、バインディング、配置計画を生成します。すべて日本版の合成設定であり、実際の需要や食品品質を示しません。

## 再生成

```powershell
npm run data:export
```

実行位置はプロジェクト直下です。データ生成はネットワーク通信、資格情報の読み取り、クラウド書き込みを行いません。生成対象のローカルファイルは上書きするため、データを編集するときは入力定義を変更します。リモート配置後の `ontology/fabric.generated.json` は生成処理の対象外です。

入力はレビュー原文や配合を簡潔に保持します。生成処理が合成の注文・明細・レビュー ID を決定的に付与し、購入→受取→投稿の時系列を構成します。実 EC 取引から収集した記録ではありません。

## 日時と識別子

- 履歴レビューは 2026 年 5～6 月、合成分析基準は 2026-07-08 18:00 JST です。
- 保存日時はオフセット付き ISO 8601、画面表示は `Asia/Tokyo` です。UI の日付範囲は開始日の 00:00:00 から終了日の 23:59:59.999 までを含みます。
- `ORD-DEMO-0702` / `LINE-DEMO-0702` は神田店で PRD-002 を 2 杯購入し受取済み。税抜 1,200 円＋税額 96 円＝税込 1,296 円です。
- 6 月の SHP-0040 / SHP-0042 と 7 月の SHP-JP-0703-04 / 06 を分離しています。
- 自動生成する CSV 全行に `datasetId` を付けます。飲料の画面用 JSON は最上位に同じ値を持ち、ブレンドは親アプリから同じ識別子を使用します。ID の再利用を理由に他データセットと結合しません。

## レビューの母数

有効レビューは、基準時点で明細ごとの最新版、公開済み、分析済み、本人の完了注文、投稿前の受取完了を満たすものです。商品・店舗・期間も適用します。後続版が非公開なら古い公開版へ戻しません。

初期の PRD-002 は 24 件、甘さ控えめの要望は一意レビューで 12 件、50.0% です。6 店舗に各 4 件・要望 2 件を意図的に配置した比較用教材で、統計的な代表性はありません。PRD-003 の別レビューは 6 件です。

[events/review-published.json](events/review-published.json)を画面から取り込むと、同じ期間・全店舗・PRD-002 で 25 件中 13 件、52.0% になります。神田店は 5 件中 3 件です。同一イベントの再取込は加算せず、内容が変わった同一 ID は拒否します。

同ファイルは、公開審査と分類が完了した状態を表す**合成の入力例**です。ローカル版は審査や AI 分類を実行していません。未公開、分析前、撤回の状態は集計に含めません。取消注文は商品レビューを持ちません。

話題は別テーブルで複数付与できます。割合の分子は一意レビュー数で、複数話題の割合を足して 100% に合わせません。サービス不満は独立して 2/4 件であり、商品レビュー 24 件に混ぜません。

## 複数情報源の統合

[voice-sources.json](voice-sources.json) は手編集する追加の合成原本です。版は `2026-09-10.voices-1`、識別子と基準時点は既存データと共通です。アンケート 14 件、SNS 14 件を収録しています。この 28 件は上記の 40 テーブル・334 行には含めず、生成スクリプト、CSV、Ontology 定義・バインディングの対象にも追加していません。再生成で上書きされません。

| 情報源 | PRD-002 の初期件数 | 評価の意味 | 採用条件 |
|---|---|---|---|
| レビュー | 24 | 購入した商品の 1～5 の評価 | 既存の購入・受取・公開・最新版・分析済み条件を維持 |
| アンケート | 12（評価回答 11） | 選択商品の満足度。1＝不満、5＝満足 | 公開済み・分析済み。購入者本人かは未確認。未回答は null |
| SNS 口コミ | 13（店舗不明 1） | 星評価なし | 公開済み・分析済み。購入確認なし。文章から星を推定しない |
| EC チャット | 顧客発言 13（7 会話、店舗不明の発言 1） | 星評価なし | 分析対象・分析済み会話の顧客発言だけ。AI 返答・商品未指定の発言は除外 |

PRD-003 はレビュー 6 件、アンケート 2 件、SNS 1 件、EC チャットの顧客発言 2 件（1 会話）です。SNS・チャットの店舗不明原文は全店舗選択時だけ含め、特定店舗への絞り込みとランキングには含めません。店舗や商品との関連付けは合成原本に明示した ID であり、AI による実投稿の推定結果ではありません。

- 商品・店舗・期間・情報源を共通条件として適用します。空欄・逆転した日付範囲は 0 件です。基準時点より後の投稿・分析を除外します。
- アンケート・SNS の原本は `source` と `id` で同じ記録を識別し、基準時点で最新の `revision` を選んでから公開・分析条件を適用します。撤回された記録の旧公開版を復活させません。
- 統合 62 件は投稿・回答・顧客発言の件数であり、顧客人数ではありません。同一人物の情報源間の重複照合は未実装です。複数回発言するチャットは、1 投稿のレビューより件数が増え得ます。市場需要、販売見込み、顧客母集団の推定には使いません。
- 商品レビュー平均は 4.08、アンケート満足度平均は 47 / 11 = 4.27 です。両者の平均を合算しません。SNS・チャットの評価は null とし、サービス評価 2/4 件は別の注文評価として維持します。
- 店舗ランキングは、選択商品の評価元別の単純平均です。有効な 1～5 の整数回答のみを用い、件数を併記します。同じ平均は同順位（1、2、2、4）。最低件数を下回る店舗には順位を付けず、評価なしを 0 点にしません。少数回答の順位が安定しているという保証はありません。
- 原文の「話題」「語」は掘り下げ条件です。時系列投稿数・ワードクラウド・ランキングの母数を狭めず、原文と店舗ごとの該当数を絞ります。店舗の棒やランキングからの掘り下げでは選択中の語・話題を保持します。

### 時系列投稿数

左上の棒グラフは、商品・店舗・期間・情報源で選択された有効な声を JST の日別に集計します。横軸は `timestamp` の連続時間軸、縦軸は 0 起点の整数件数です。レビュー・アンケート・SNS は `publishedAt`、チャットは顧客発言の `sentAt` を使い、取込日時や分析日時では数えません。1 件の単位は投稿・回答・顧客発言であり、人数・会話数ではありません。

各棒は当日 00:00 以上、翌日 00:00 未満の件数を表し、その日の中央に配置します。選択期間全体の時間間隔を保ち、0 件の日は棒を描画しません。日別の表も投稿がある日だけを昇順に表示します。棒の合計は「対象の声」と一致し、初期商品では 62 件・40 日分です。該当なしと日付未入力は別の状態として表示します。

実装: [日別集計](../src/voice.ts)、[時系列描画](../src/VoiceTimeline.tsx)。描画ライブラリ: [Recharts](https://recharts.github.io/)。

### 肯定・中立・否定

[voice-sentiments.json](voice-sentiments.json) は既存の合成原文 73 件に付けた独立した手動分類です。実サービスによる感情分析、星評価からの換算、実行時の辞書推定ではありません。40 テーブルの生成処理、Fabric 定義、判断保存には追加していません。

- `overall` は原文全体の分類です。明示的な不満を否定、次に明示的な好意を肯定、それ以外の質問・希望・事実を中立とします。好意と不満が混在する原文は全体では否定になり得ます。これは今回の合成分類方針であり、一般的な分類精度を示しません。
- `topics` は既存の各話題に関する分類です。例えば `SNS-008` は全体と「待ち時間」が否定、「香り」「後味」は肯定です。甘さ控えめの希望があるだけで否定にしません。「現行支持」の発言を、商品への否定と取り違えません。
- 情報源を含む原文 ID と本文の完全一致で分類を適用します。追加投稿、変更済みの本文、未登録の話題は「未分類」です。未分類を中立や否定率 0% へ変換しません。本番の分類版・分析時刻・信頼度・監査履歴は未実装です。
- 積み上げ棒の分母はその行の全件数で、未分類も別の模様で含みます。否定率の分母は肯定・中立・否定の分類済み件数だけです。分類済みが 0 件なら `-` と表示します。
- 店舗別は一原文を一店舗へ集計し、店舗不明を独立した行にします。話題別は一原文が複数行に入るため、行の件数合計を全体件数と比較しません。
- 商品・店舗・期間・情報源に加え、既存の語・話題の原文条件にも連動します。行や感情区分の選択は原文だけをさらに絞り、グラフの母数は維持します。選択解除で元の原文集合へ戻ります。

初期 PRD-002 の全体分類は肯定 32・中立 20・否定 10・未分類 0、計 62 件です。浦和は否定 4/10 件（40.0%）。チャット単独は肯定 3・中立 7・否定 3、計 13 発言です。市場・顧客全体の比率、店舗の総合評価、改善の因果効果には外挿しません。

実装: [分類と集計](../src/sentiment.ts)、[グラフ](../src/VoiceSentimentChart.tsx)。

### ワードクラウド

[語集計](../src/voice.ts)は NFKC 正規化、業務語の辞書、ブラウザー標準の `Intl.Segmenter` による語分割、除外語を使用します。AI 分類・感情分析・辞書学習は行いません。否定・皮肉・要望の意味までは判定できません。語を含む投稿を 1 件として数え、同一本文内で繰り返しても増やしません。

上位 28 語を対象に [d3-cloud](https://github.com/jasondavies/d3-cloud) で衝突を避けて配置します。小さい描画領域では配置できない語があり、「語別の件数」には対象語すべてを表示します。語の選択・解除とキーボード操作で原文を確認できます。分割 API の仕様: [Intl.Segmenter](https://developer.mozilla.org/ja/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter)。

話題タグと文字として現れる語の頻度は別です。例えば初期レビューの「甘さ控えめ」は、意味を付けた話題タグでは 12 件ですが、同じ語を直接含む原文は 4 件です。統合した「香り」の原文は 26 件（うちチャット 2 発言）です。

実装: [統合・語集計・順位計算](../src/voice.ts)、[顧客の声画面](../src/CustomerVoices.tsx)、[ワードクラウド描画](../src/VoiceWordCloud.tsx)。外部 API、Fabric 接続、実投稿 URL はありません。飲料の判断保存は既存レビュー ID だけを含み、この追加原本・語・順位は保存しません。

### EC チャット履歴

[ec-chat-history.json](ec-chat-history.json) は EC の「バリスタに相談」を想定した独立した合成会話です。版は `2026-09-10.chats-1`。8 会話・32 発言（顧客 16、AI 16）を収録し、顧客発言のうち 1 件は商品未指定です。実 EC から収集した会話・実音声文字起こしではありません。既存の 40 テーブル・334 行、生成処理、Ontology 定義、判断保存には追加していません。

- `role=customer` の発言だけを件数・話題・語頻度へ加算します。同じ会話で同じ語を別の発言に含めれば、発言ごとに数えます。会話数は対象発言が属する会話 ID の一意数です。
- `productId` は発言単位です。商品未指定の発言や AI だけが薦めた商品は、顧客の要望へ推定して加算しません。話題タグも合成原本で明示しており、実行時の AI 分類ではありません。
- `storeId` は合成会話の受取予定店です。来店・購入・履行済みの証拠ではありません。未指定は null とし、特定店舗へ配賦しません。
- `channel` はテキスト／音声文字起こしを区別する合成設定です。音声データや実サービスの文字起こし結果は収録していません。
- `status=included` かつ基準時点までに分析済みの会話から、期間内かつ基準時点以前の顧客発言を抽出します。撤回済み・未分析会話は対象外です。同じ会話 ID・発言 ID の重複は一度だけ数えます。発言編集の版履歴は未実装です。
- 原文の「会話履歴」には基準時点以前のやり取りを話者別に表示します。AI の返答は集計対象外と明示し、期間外・商品未指定の発言も文脈として区別します。全体の履歴表示を集計件数とは数えません。
- 例として `CHAT-006-U1` の「甘さ控えめに一本化しないでほしい」は「現行支持」です。単語が現れることを、その変更への賛成と解釈しません。

[EC の実装](../../maikuro-coffee-shop-v2.html) は現在の画面内で会話を保持します。この分析画面との自動同期、エクスポート／取込、永続的な履歴 API は今回追加していません。実連携には顧客の同意、個人情報の除去、履歴の認可、削除反映、商品・店舗の関連付け、実時刻と分析基準時点の整合が必要です。実会話をこの静的 JSON へ埋め込んで配信しないでください。

## 飲料計算の前提

必要原料量 = 1 杯の配合量 × 想定杯数 ÷ (歩留まり / 100)。単価は `pricePer100Units`、単位は mL・g・each です。包材の each は一組を表します。表示では円を丸めますが、計算途中は丸めません。

利用可能量 = 基準時点の在庫 − 既存予約量 ＋ 基準時点後かつ展開開始日の 00:00 JST までの確定入荷。不明な在庫は null を保ち、未来の到着実績を取り込みません。未登録店舗も「在庫 0」ではなく確認不能です。

開始日の途中や期間途中の入荷は含めない保守的な開始時点計算です。日々の在庫最適化、日中の入荷、追加の既存需要、同一入荷の複数期間への配賦、需要予測は実装していません。既存予約以外の将来需要がない仮定を超えて発注判断へ使用しないでください。

基準期間 7/14～7/20、神田 100 杯・横浜 60 杯では A の税抜変動費 35,200 円、B は 41,600 円。B の MAT-02 は神田で 25,000 mL、横浜で 15,000 mL 不足します。MAT-03 の在庫は不明なので、C の不足量は確認不能です。

原価と利益の範囲は [商品仕様](../knowledge/internal/product-spec.md) に定義します。食品安全性・表示の適合は未確認です。

## ブレンド計算の前提

豆の原本は別版 `2026-09-10.blend-1`、分析基準日時は共通です。比率は焙煎後質量比、生豆必要量は g で計算します。店舗袋数を全体で合計し、中央在庫から既存引当を一度だけ控除します。製造日当日の入荷は時刻不明のため含めません。飲料の杯数、冷蔵設備、価格上限は使いません。

エチオピア在庫は null、納期不明の未確定入荷は不算入です。原料費は補充見積基準であって会計在庫原価ではありません。数式、具体例、代替供給元の承認・納期、未モデル化の実ロットは [ブレンドシナリオ](../blend-scenario.md) に記載しています。画面の変更は生成済み初期案やクラウドデータを書き換えません。

## 欠損と Fabric 用投影

分析用 CSV は null を空欄として保持します。空欄はゼロではありません。`ontology/data/` は既存デプロイヤーの非空値条件に合わせた別の投影で、null を文字列「未確認」、Boolean を文字列 `true` / `false` に変換します。

投影列に文字列「未確認」が含まれる場合、その列の型は String です。例えば `onHand`、`reserved`、`cupsPerDay`、`aromaScore` は数値集計用ではありません。算術には分析用データを使用します。既知の整数だけの列は BigInt とします。[manifest.json](manifest.json)の型定義は **Ontology 用投影**の型です。
