# Micro Coffee シナリオ

日本市場向けの「舞黒珈琲店」の原本・意味定義・根拠文書を、アプリ本体や配備先から分離して移植しました。加えて、[世界銀行のコーヒー価格](reference-data/world-bank-coffee/README.md)を独立した公開実データとして同梱しています。合成の受注・会話を実業務データとして扱いません。

移植時の由来は [sources.lock.json](sources.lock.json)、分析の 26 テーブル定義は [table-schemas.json](table-schemas.json) です。公開価格には別の出典記録があり、選択すると 1 テーブルを追加します。[データ基盤手順書](../../docs/data-foundation.md)で準備と配備を行います。

元ディレクトリの [予測スナップショット](data/predictions.json) と ML 入力 13 ファイルも無変換で同梱しています。`prepare --include-predictions` は元と同じ予測結果の 3 テーブルを加え、基本構築を 29 テーブルにします。学習・モデル登録をやり直す処理ではありません。予測・ML 入力・RTI 定義の追加移植 15 資産は [出典記録](../../docs/provenance/setup-assets.json) にまとめています。DB・アプリ・IQ への投入順序は [E2E 構築手順](../../docs/end-to-end-setup.md) を参照してください。

## デモ実演マニュアル

[舞黒珈琲店の通し台本](demo/README.md) に、開始準備、約 25 分の進行、画面操作、話す内容、数値の期待値、IQ に送る質問、失敗時の代替進行、終了・復元をまとめています。

EC → 顧客の声 → 商品開発 → 供給と注文 → 過去の却下理由と現行規定の照合、の順に進みます。クラウド未接続でも行えるローカル版と、IQ / Fabric の実接続版を分けています。世界銀行の公開価格を示す追加説明もあります。台本と期待回答は検索索引へ投入しません。新環境でのクラウド接続を含む通し実演は未確認です。

## 内部構成

```text
micro-coffee/
|-- data/             EC・業務分析の合成原本、生成条件、対応表
|-- ontology/         商品開発・供給の意味定義と明示的なデータ型
|-- knowledge/        根拠文書の合成原本、出典 ID、版、有効期間
|-- ml-data/          元の学習入力 CSV・Parquet・JSON と集計
|-- prompts/          Agent の業務指示、読み方、許可する業務操作
|-- reference-data/   公開コーヒー価格の固定スナップショットと利用条件
|-- assets/           再配布条件を確認した画像・表示資産
`-- demo/             実演台本、期待結果、未接続時の実演範囲
```

プラットフォームに依存しない原本をここに置き、Fabric のネイティブ定義・PostgreSQL の投入形式・画面用スナップショットは原本から生成します。元の JSON オントロジーを、そのまま Fabric の API ペイロードや OWL と呼びません。

## シナリオに必須とする情報

| 項目 | Micro Coffee の方針 |
| --- | --- |
| 識別 | シナリオ ID、原本の版、元データの ID 対応を明示 |
| 日本語 | 表示名・読み方・Agent の業務用語をまとめて管理 |
| 金額 | JPY、税抜・税込の区別、品目別税率、端数処理を明示 |
| 時刻 | UTC の保存時刻と Asia/Tokyo の表示・集計境界を区別 |
| 数量 | g・kg・袋・杯を区別し、確認済みの換算だけを使用 |
| 欠損 | 在庫・入荷・対応不明をゼロや推定値へ置換しない |
| データ由来 | 合成・実業務データを区別。実サービスから取得しても合成原本は合成のまま |
| 利用する機能 | EC、業務、IQ、音声、RTI、ML の依存と必須入力を宣言 |
| 再現性 | 生成条件、基準日時、期待結果、許可された配布範囲を記録 |

原本の出典記録・テーブルスキーマ・データ準備処理は実装済みで、`demo/` には実演マニュアルを配置済みです。`assets/` は今後の配置先で、動的なシナリオ切替や別業種への汎用変換はまだありません。

## 原本を統合するときの注意

EC のカタログと業務分析の原本は対象範囲が異なります。現在の 18 商品の EC カタログと 12 商品の分析教材、開発用の配合・材料を無理に同一集合へそろえません。共通の商品・店舗・供給会社は対応表で管理し、対象外・未対応も記録します。

既存の顧客の声と EC チャット履歴は合成教材です。実 EC の相談が自動収集され、分析から新商品登録まで自動反映される構成ではありません。需要予測の学習用の仮定も、業務上確認済みの商品・配合対応として流用しません。

次のシナリオはこの構造を基に追加します。ただし、異業種では画面、計算、承認、データ接続自体の拡張が必要になり得ます。ファイルの置換だけで全業種に対応できるとはしません。
